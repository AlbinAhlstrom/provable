# ADR-007: Product Intent Step Before Domain Decomposition

## Context
Tracing "A personal website for a babysitters firm" showed that the decomposition prompt turns every pitch into a back-office DDD model: it produced Babysitter, FamilyClient, Child and Booking with lead-time, capacity and cancellation rules, i.e. a booking operations console. Nothing in the pipeline decided what kind of product the pitch asked for.

## Decision
Kickstart now has a first step, `onboarding/intent.py` with `prompts/intent_classification.md`: one JSON-mode LLM call returns a `ProductIntent`:
- `product_type`: `public_website | customer_app | internal_tool | api_service | marketplace | game | data_pipeline | other`
- `audience`, `primary_goal`, `scope_summary`
- `model_focus` (what the model must cover), `out_of_scope` (what it must not model), `assumptions`

The intent is injected into `router_decomposition.md`, which must scope entities and BDD rules by it. It is persisted with the kickstart state (`intent_json` column, auto-migrated), returned by `/api/onboarding/kickstart` and `/api/onboarding/aggregates`, and shown as a banner in PM Studio (covered items green, excluded items red) so it can be challenged.

An unusable answer raises `IntentError`; there is no default intent (retries and fallbacks mask errors).

## Evidence (live, same pitch, 3 runs)
All three runs classified the pitch as `public_website` and produced content-oriented models (ServiceOffering, BabysitterProfile/CaregiverProfile, ContactEnquiry/ServiceInquiry, plus Testimonial and FAQ in one run) with specs about enquiry validation and profile rules, and none of the booking, lead-time or capacity concepts. Entity names and spec details still vary between runs, within a consistent frame.

## Consequences and gaps
- One extra LLM call (about 4 s at low reasoning effort) per kickstart.
- Intent quality depends on the model; the banner and the stored assumptions make a wrong classification visible, but there is no UI yet to edit the intent and re-run decomposition.
- The generated workspace is still a domain skeleton with CRUD routers; a presentation layer for a `public_website` intent (pages, content) is not generated by this repository's pipeline.

## Status
Accepted.
